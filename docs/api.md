# Public API v1

Base URL: `http://127.0.0.1:8765`. WebSocket uses `ws://` (use `wss://` behind TLS). This API does not provide authentication, persistence or reconnect restoration.

| Endpoint | Purpose | Success |
| --- | --- | --- |
| `GET /health` | Process/HTTP handler alive; does not invoke providers | 200 `{"status":"ok"}` |
| `GET /v1/capabilities` | Version, configured services, formats and effective limits | 200 JSON |
| `POST /v1/audio/speech` | Client text → TTS | 200 audio bytes, normally `audio/wav` |
| `WS /v1/realtime` | Conversation or client-supplied response generation | `session.created`, protocol 1 |
| `WS /v1/transcription` | Input PCM → final transcript, no conversation/LLM | `session.created`, protocol 1 |

Discovery is a separate HTTP endpoint so SDKs can inspect availability before opening a socket or microphone. A separate readiness route is unnecessary: capabilities expose **configured availability**, not a live inference probe. `available: true` does not guarantee a remote provider or sidecar is currently reachable. `/health` remains successful when no providers are configured.

## Speech HTTP request

```sh
curl -i http://127.0.0.1:8765/v1/capabilities
curl -D speech-headers.txt -o speech.wav http://127.0.0.1:8765/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{"text":"こんにちは","voice":"f1","speed":100}'
```

Required `text`: non-whitespace UTF-8 string, at most 32768 bytes. Optional `provider` selects a configured TTS name; empty chooses the default. `voice` and `speed` are provider-specific, with speed nonnegative; AquesTalk defaults to 100. Unknown JSON request fields and multiple JSON values are rejected. The body limit is separate from the decoded text limit. Do not assume sample rate from provider identity: read `X-Audio-Sample-Rate` and `X-Audio-Channels`. `X-Request-ID` is always generated by the server, including errors and preflight responses.

Failure before response headers uses [the structured HTTP error schema](errors.md). A failure after audio streaming has started cannot replace an already-sent 200 with JSON; it terminates the stream and is logged against the request. The client must detect incomplete audio.

## Capability model

The response includes `protocol_version: "1"`, an `endpoints` map, `features`, `input_audio_formats`, `output_audio_formats`, and numeric `limits`. Features are named, versioned records, not arbitrary top-level flags:

```json
{
  "protocol_version": "1",
  "features": {
    "transcription": {"version":"1","available":true,"modes":["commit","final-only"]},
    "audio_flow_control": {"version":"credit-v1","available":true,"modes":["credit-v1","legacy-bounded"]}
  }
}
```

Other feature keys: `tts`, `conversation`, `realtime_audio`, `realtime_input`, `interruption`, `backchannel`, `speculation`. Conversation availability requires configured LLM; audio conversation also requires TTS. Realtime input requires STT and a turn detector. Transcription-only requires only STT. Provider class/name, keys, model names/paths, prompts and filesystem locations are not returned.

Each feature's version describes that feature's wire semantics. `session.configure` validates protocol version and optionally selects audio flow control. Optional features do not require the client to handle extra events; ignore unknown server events/fields. STT speculation remains a transparent server optimization and never creates public precommit PCM.

Input format is `{"encoding":"pcm_s16le","sample_rate":16000,"channels":1}`. Output formats list `pcm_s16le` and `wav`; omitted output `sample_rate` means it is determined per response, not arbitrary input resampling support. WebSocket output is mono PCM16; HTTP speech returns the configured provider's declared format.

## Limits and timeouts

Numbers below are defaults; discover configured conversation/endpoint/speculation values from capabilities. Transport limits are centralized in `internal/protocol/protocol.go`. Source-frame audio limits remain owned by the Audio Runtime.

| Limit | Value / scope |
| --- | --- |
| Client WS JSON | 65536 UTF-8 bytes per complete message, including envelope |
| Client WS binary | 65536 bytes per complete message; fragmented frames count together |
| Server audio binary | 16384 bytes per packet, further reduced to available credit |
| HTTP JSON body | 1048576 bytes |
| Decoded input/TTS text | 32768 UTF-8 bytes; conversation configuration may be stricter |
| Final STT transcript | 16384 UTF-8 bytes; independent of input JSON and PCM limits |
| Manual input turn | 120 seconds = 3,840,000 PCM bytes, realtime legacy and transcription |
| Continuous input turn | Default 120 seconds; configured maximum up to 10 minutes |
| Conversation | 50 items, 256KiB store, 32KiB/item; context 20 items / 48KiB, 1024 audio chunks |
| Worklet PCM | 30 seconds hard capacity, separate fixed 4096 metadata descriptors |
| Audio send window | Recommended credit-v1; legacy 2 seconds, replenished by playback ACK |
| Concurrent STT | 2 per server, shared by realtime, transcription and speculation |
| WS connections | 64 per server |
| Transport workers | 16 per socket, including update consumers and generation workers |
| Speculation | 1 active worker/session, 3 attempts/turn, 2s cooldown, 45s lifetime, 16KiB transcript, 64KiB/1024 deltas |
| STT / TTS provider calls | 2 minutes; provider must honor context cancellation |
| WebSocket write | 10 seconds including writer-lock admission; metadata/binary pair shares deadline |
| Audio credit wait | 30 seconds; independent of connection liveness |
| Runtime/worker cleanup | 2-second shared wait budget; final write and close handshake separately bounded |

There is no application idle/read timeout: a quiet session or long turn is not treated as disconnected. The websocket library handles protocol ping/pong while reading; optional JSON `ping` gets `pong` for SDK diagnostics. This is not automatic reconnection. See [coder/websocket v1.8.15 documentation](https://pkg.go.dev/github.com/coder/websocket@v1.8.15#Conn.Ping).

Oversized input messages receive `payload_too_large` when possible, followed by WS close 1009. Invalid JSON/unknown client events receive a recoverable error without immediately closing. Exceeding a manual turn budget discards that turn; start a new one. There is no application request-per-second quota; concurrency and memory bounds provide resource admission, reported as `resource_limit`.

## Browser Origin and CORS

Default: no-Origin native clients, same-origin HTTP(S), and HTTP(S) loopback origins (`localhost`, `127.0.0.1`, `::1`, any port) are allowed. Other browser origins require an exact `AllowedOrigins` entry; the engine entry point reads comma-separated `API_ALLOWED_ORIGINS`. Embedders can disable the loopback exception through `Config.DisableLocalOrigins`.

No wildcard origin, no `Access-Control-Allow-Credentials`. Allowed origins are echoed; `Vary: Origin` is set. Preflight supports the route method and `Content-Type`. Exposed response headers are request ID and audio format headers. HTTP and WebSocket use the same policy. `Origin: null` (typically file pages) is rejected unless explicitly configured. For Electron/browser development, serve the sample over localhost HTTP. Native clients do not need to invent an Origin header.

Origin policy is not authentication or a substitute for network access control. The entry point binds loopback. Cloud deployment/authentication are outside this version.
